## 一、目标：先定义清楚三件事（不写下来别动手）

### 1.1 SMART 目标模板

| 字母 | 含义 | 反例 | 正例 |
|------|------|------|------|
| **S** Specific 具体 | 一句话说清做什么 | "做好产品" | "上线 MVP 包含 A/B/C 三个功能" |
| **M** Measurable 可衡量 | 有数字 | "提升质量" | "把首次响应时间从 24h 缩到 4h" |
| **A** Achievable 可达成 | 跳一跳够得着 | "本季度做到 1000 万"（无基础） | "本季度做到 80 万（前季 50 万）" |
| **R** Relevant 相关 | 对业务有意义 | "搞个新技术栈 demo" | "上线 CRM 让销售跟进效率提升 30%" |
| **T** Time-bound 有时限 | 明确的截止日 | "尽快" | "6 月 30 日前完成" |

### 1.2 范围：明确"不做什么"（防蔓延）

每个项目启动时**先列出"不做清单"**——这是项目超期的第一防线。

| 必做 | 不做 |
|------|------|
| 移动端登录 | 第三方登录 |
| 基础数据导出 | Excel 高级公式导出 |
| 5 个核心报表 | 自定义报表 |

> 客户/老板中途加需求是常态。**重新走排期 + 谈钱**——"这个可以加，我先评估对原计划的影响，再给你一个补充报价。"

### 1.3 验收标准：先写下来再动手

> 例子：「登录功能验收 = 支持手机号验证码登录 + 错误提示 + 30 分钟无操作自动退出」

- **验收方**是谁？客户？老板？技术总监？
- **验收方式**：邮件确认？签字盖章？自动化测试？
- **争议处理**：验收不通过的标准是什么？返工谁负责？

## 二、拆解与排期

### 2.1 WBS（工作分解结构）：把大目标拆成 1–3 天的小任务

**例子：「上线 MVP」拆解（节选）**

```
上线 MVP
├── 需求评审（1 天）
├── 设计稿（3 天）
├── 后端开发
│   ├── 数据库设计（1 天）
│   ├── API 接口（5 天）
│   └── 单元测试（2 天）
├── 前端开发（5 天）
├── 联调测试（3 天）
├── 部署上线（1 天）
└── 验收文档（1 天）
```

- **每条任务 1–3 天能完成**——太长说明没拆透。
- **谁负责、什么时候交付、依赖谁**——三条都标清楚。

### 2.2 关键路径法（识别"卡脖子"任务）

**关键路径 = 项目最长链路 = 决定项目总时长的那串任务**。

- 用纸或看板标出"如果这个任务延后 N 天，整个项目就延后 N 天"的任务——它们是关键路径。
- 关键路径上的任务 = 多给资源 + 多留缓冲 + 优先做。
- 非关键路径上的任务 = 可以晚点做（但不能晚到影响关键路径）。

> **速算法**：最简单项目 = 关键路径总时长 + 20–30% 缓冲。

### 2.3 排期别排满（预留 20–30% 缓冲）

- **一定会有**：需求变更、bug、人员请假、生病、客户拖反馈。
- 排满 100% = 第一个意外就延期；延期就开始加班；加班就出错；出错就崩盘。
- **缓冲放在关键路径上**——非关键路径上的小延后不影响大局。

### 2.4 工具选择（小团队够用版）

| 场景 | 推荐 | 不推荐 |
|------|------|--------|
| 任务看板 | Trello / 飞书多维表 / Notion / 钉钉任务 | Jira（小团队重） |
| 文档沉淀 | 飞书云文档 / Notion / 语雀 | 散在微信聊天 |
| 进度同步 | 每周一 15 分钟站会 + 看板截图 | 每天 1 小时例会 |
| 文件存储 | 飞书/Notion + 重要文件本地备份 | 仅靠个人电脑 |

> **原则：工具是为流程服务的，工具本身不是流程**。看板挂墙上每周看，比上最贵的系统重要。

## 三、执行：盯进度、防失联

### 3.1 每周进度快照模板（复制即用）

```
【第 X 周 项目进度】
📌 本周完成：
- ✅ [任务 1]
- ✅ [任务 2]
🚧 进行中：
- [任务 3] 进度 70%，预计 X 日完成
⛔ 卡点：
- [任务 4] 等待 XX 提供 YY 资料（已催第 2 次）
📅 下周计划：
- 完成 [任务 3] [任务 5]
🎯 关键节点：
- X 月 X 日前完成 MVP 联调（还有 10 天）
```

### 3.2 卡点早暴露原则

- **问题拖过一周通常会翻倍恶化**。
- 暴露三步骤：① 自己先想 1 个应对方案；② 找能拍板的人（老板/客户/同事）；③ 讲事实+方案+请求，别只讲问题。
- **别等"周会再说"**——周会解决的是上周的问题，不是这周的。

### 3.3 外包/协作管理

- **小单试水**：先合作 1–3 个小额订单（几千–几万元），验证质量、交期、沟通。
- **关键条款**写进合同：交付物清单、验收标准、时间节点、付款节点、违约责任、保密、知识产权归属（参考 [附录/02-常用模板与术语](../附录/02-常用模板与术语.md)）。
- **阶段验收 + 阶段付款**：30% / 40% / 30% 三段，别一次付清。
- **里程碑会议**：每到节点开 15 分钟视频会，确认进度+下一步+答疑；不要纯文字拖。

## 四、风险登记册（小项目也建议做）

| 风险 | 影响 | 概率 | 应对 | 责任人 | 触发动作 |
|------|------|------|------|--------|----------|
| 客户中途加需求 | 延期 2 周 | 高 | 提前签补充协议+加价 | PM | 收到需求当天评估 |
| 关键人员请假 | 关键路径停 | 中 | 关键岗位配 B 角 | 项目经理 | 请假申请即触发 |
| 技术方案不可行 | 延期 1 月 | 低 | 每 2 周技术评审 | 技术负责人 | 评审不通过即触发 |
| 第三方服务延期 | 部分功能延迟 | 中 | 提前 2 周下单 | 采购 | 收到订单即触发 |

> **关键**：触发动作要明确——"如果发生 X，就做 Y"——别等真出事了临时想。

## 五、复盘：项目结束必做（5 分钟版本）

### 5.1 三问复盘（最小可用）

```
1. 做对了什么？（保持）
2. 哪里浪费了？（下次省）
3. 下次怎么改？（写进 SOP/模板）
```

### 5.2 深度复盘模板（重要项目用）

| 项目 | 内容 |
|------|------|
| **目标 vs 实际** | 原计划 vs 实际达成（时间/范围/成本/质量） |
| **关键偏差** | 哪里和计划差最多？ |
| **根因** | 为什么差？（5 Why 追问） |
| **学到什么** | 新认知、新方法、新教训 |
| **下次怎么改** | 具体动作（写进 SOP / 模板 / 流程） |
| **沉淀物** | 新模板 / 新清单 / 新规则 |

### 5.3 复盘频率

| 频率 | 适用 |
|------|------|
| 每个小任务结束 | 5 分钟，3 问 |
| 每个里程碑完成 | 30 分钟，5 问 + 沉淀物 |
| 每个项目收尾 | 1 小时，深度复盘 + 团队分享 |
| 每月 | 月度复盘（所有项目的合集） |
| 每季度 | 跨项目的方法论复盘 |

## 六、看板建法（5 分钟搭起来）

### 6.1 三栏看板（最简）

```
[待办 To Do]  →  [进行中 Doing]  →  [已完成 Done]
```

### 6.2 五栏看板（推荐）

```
[待办] → [计划中] → [进行中] → [待验收] → [已完成]
```

- **每张卡片写**：任务名 + 负责人 + 截止日 + 验收标准（一行字足够）。
- **WIP（在制品）上限**：每个人同时进行的任务 ≤ 3 个——多了质量必然下降。
- **每日站会**：每人 1 分钟——昨天做了什么 / 今天做什么 / 卡点是什么。**不开成例会**。

### 6.3 看板 5 不要

- ❌ 把看板当摆设（不更新 = 没用）
- ❌ 卡片只写标题不写验收标准
- ❌ 任务 30 天还在"进行中"（要拆、要删、要重排）
- ❌ 所有人共享一张大看板（个人/小团队各管各的）
- ❌ 把"等别人"也算在 WIP 里（要明确责任人）

## 七、外部协作与客户预期管理

### 7.1 与客户/老板同步节奏

| 阶段 | 同步频率 | 同步内容 |
|------|----------|----------|
| 立项 | 1 次 | 目标、范围、时间、预算、风险 |
| 执行中 | 每周 1 次 | 进度、下一步、问题 |
| 里程碑完成 | 即时 | 交付物 + 验收请求 |
| 风险变化 | 即时 | 新风险 + 应对方案 |
| 项目收尾 | 1 次 | 验收 + 复盘 + 下一步 |

### 7.2 进度同步的话术

- **进度正常**："按计划推进中，本周完成 X，下周做 Y，预计 X 月 X 日交付。"
- **进度落后**："原计划 X 月 X 日完成，目前进度 70%，预计延迟 X 天。原因是 [客观原因]，建议 [应对方案]，需要您 [具体支持]。"
- **范围变化**："您提的 Z 是新需求，评估影响：时间 +X 天 / 费用 +X 元。补充协议签字后我立即安排。"

## 八、常见坑速查

| 坑 | 后果 | 怎么避免 |
|----|------|----------|
| 没有书面目标 | 各干各的、交付不一致 | 立项文档 1 页 |
| 一个人闷头做 | 没计划没复盘、信息孤岛 | 周快照 + 月复盘 |
| 客户中途加需求不重排期 | 永远"快好了"、质量崩 | 改范围 = 重谈三件事（时间/钱/范围） |
| 文档只在嘴上 | 人一走信息就断 | 关键决策留文档（飞书/Notion） |
| 缓冲为零 | 一个意外就延期 | 关键路径留 20–30% 缓冲 |
| 关键岗位单点 | 一个人请假/离职全停 | 关键岗位配 B 角 + 文档化 |
| 验收标准模糊 | 反复返工还扯皮 | 验收标准先写下来 |
| 复盘只追责 | 下次大家藏问题 | 复盘对事不对人、聚焦改进 |

## ✅ 本节行动清单

**新项目立项时：**
- [ ] 写 1 页立项文档（目标 / 范围 / 验收 / 时间 / 资源 / 风险）
- [ ] WBS 拆到 1–3 天小任务，标责任人和截止日
- [ ] 建项目看板（哪怕只有 3 栏）
- [ ] 设关键路径 + 缓冲
- [ ] 与相关方约定同步节奏

**项目执行中：**
- [ ] 每周发进度快照（固定时间，固定格式）
- [ ] 卡点早暴露：超过 3 天没进展 = 主动同步
- [ ] 范围变化 = 重谈时间/钱/范围 + 书面确认

**项目收尾：**
- [ ] 验收清单逐项打勾
- [ ] 5 分钟复盘（3 问）+ 重要项目深度复盘
- [ ] 把"下次怎么改"沉淀成 SOP / 模板
- [ ] 归档：项目文档 + 复盘文档
